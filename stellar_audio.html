SUBSYSTEM OVERVIEW

Stellar Audio est un sous-système audio (UWorldSubsystem) pour Unreal Engine 5.7, piloté par GameplayTags et pensé pour le multijoueur dès le départ. Il centralise la lecture de sons 2D/3D derrière un pool de composants réutilisables et un acteur dédié à la réplication réseau, pour éviter les pics de garbage collection et garder la bande passante sous contrôle.

AUDIO MANAGER & OBJECT POOLING

UStellarAudioManager pré-alloue un pool de UAudioComponent à l'initialisation pour éviter toute création/destruction en jeu, source classique de spikes GC.

POOL

COMPONENT POOL

GC-SAFE 8-256
  • Pré-allocation : pool de UAudioComponent (taille configurable, défaut 32-64) créé une seule fois au démarrage.
  • Recyclage par priorité : pool épuisé ? le composant actif de plus faible priorité est recyclé plutôt que refusé.
  • Chargement asynchrone : les sons sont chargés via le StreamableManager pour ne jamais bloquer le thread de jeu.
CULL

COOLDOWN & CULLING

PERF
  • Cooldowns par son : évite le spam d'un même effet sonore en quelques millisecondes.
  • Limite d'instances : nombre maximum d'occurrences simultanées par type de son.
  • Distance culling : les sons hors de portée audible (MaxAudibleDistance) ne sont pas joués.
TAGS

DATA-DRIVEN SOUNDS

DATA ASSET
  • Registry par tag : UStellarSoundDataAsset mappe un FGameplayTag à une FStellarSoundDefinition (soft reference).
  • Découplage : le gameplay ne référence jamais un USoundBase en dur, seulement son tag.
  • Debug visuel : sphères de debug instanciées pour visualiser la portée audible en éditeur.
MODULE: NETWORK

MULTICAST REPLICATION

  • > Relais dédié : AStellarAudioReplicator est un AInfo spawné côté serveur, responsable de tous les RPC Multicast audio.
  • > Fiabilité différenciée : sons positionnels/ambiants transitoires en Unreliable (économie de bande passante), événements stop/cancel en Reliable (doivent arriver).
  • > Diffusion ciblée : possibilité d'envoyer un son à un sous-ensemble précis de joueurs (APlayerState) plutôt qu'à toute la partie.
  • > Pipeline client → serveur : UStellarAudioClientComponent sur le PlayerController expose des RPC Server pour qu'un client déclenche un son via le serveur, sans code réseau côté gameplay.

BONUS : MEDIA STREAMING LAYER

[ YOUTUBE_STREAMER_PREVIEW ]

> STREAMED MEDIA ACTORS

AStellarYouTubeStreamer étend le pooling au-delà du simple son : un acteur transitoire, géré par le même système de pool, capable de streamer de l'audio/vidéo depuis une URL internet.

  • Résolution du flux : extraction de l'URL directe via yt-dlp, mise en cache avec expiration.
  • Video-on-mesh : lecture via UMediaPlayer / UMediaSoundComponent / UMediaTexture, projetée sur un mesh de la scène.
  • Pooling partagé : les streamers sont recyclés dans le même pool que les composants audio classiques.
